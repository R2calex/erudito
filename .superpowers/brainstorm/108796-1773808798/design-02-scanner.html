Seccion 2/6 — El Scanner (Delta Detection)

El componente que detecta que cambio y dispara el ciclo de sincronizacion.

Que hace

Recorre los proyectos del registry, compara el hash del ultimo commit procesado con el HEAD actual. Si hay diferencia, extrae los deltas (archivos .md que cambiaron) y los pasa al pipeline.

Flujo del scan

scanner.py — ciclo principal
1 registry.list_all() → obtener todos los proyectos
↓ para cada proyecto
2 git rev-parse HEAD → hash actual
↓ comparar con registry.last_hash
3 Si son iguales → skip (sin cambios)
4 Si son diferentes → git diff --name-only last_hash..HEAD -- '*.md'
↓ lista de archivos .md que cambiaron
5 Leer contenido de cada archivo cambiado
↓
6 Validar metadata (frontmatter presente?)
↓ si falta → auto-enrich + label
7 Sanitizar via sanitizer-hanzo (POST /sanitize)
↓ texto limpio
8 Retornar Delta = {project, files[], new_hash}

El objeto Delta

Lo que el scanner produce
Delta: project: infra-mcp old_hash: a1b2c3d... new_hash: e4f5g6h... files: - path: README.md action: modified # modified | added | deleted content: "..." # sanitizado, con metadata auto_enriched: true # si se le agrego frontmatter - path: docs/SOP.md action: added content: "..." auto_enriched: false timestamp: 2026-03-17T14:30:00Z

A donde va el Delta

Consumidores del Delta
Scanner produce Delta
↓
Indexer
Embed en Qdrant
(rapido, local)
↓
NotebookLM
source_add + condensar
+ preguntas + notas
Ambos corren en paralelo. Indexer es rapido.
NotebookLM es lento pero no bloquea al Indexer.

Frecuencia y trigger

✓ Cron ligero: Cada 15 minutos corre el scan (solo git hash comparison, casi gratis)
✓ No hay cambios: Log interno, no molesta a nadie
✓ Hay cambios: Genera Delta, dispara Indexer + NotebookLM cycle
✓ Manual: POST /scan/{project} fuerza un scan de un proyecto
✓ Nodos remotos (Sariatu): git hash via SSH, misma logica

Decisiones de diseno

  • Solo .md por ahora: El diff filtra solo archivos .md. Podemos expandir despues (.yaml, .py) pero el 90% del valor esta en los docs.
  • Sanitizar en el scanner, no en el indexer: El texto llega limpio a todos los consumidores. Un solo punto de sanitizacion.
  • Auto-enrich aqui: Si falta frontmatter, el scanner lo agrega antes de pasar el Delta. Asi el Indexer y NotebookLM siempre reciben docs con metadata.
