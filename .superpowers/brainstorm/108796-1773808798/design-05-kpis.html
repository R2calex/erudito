Seccion 5/6 — KPIs y Metricas

Como medimos que Erudito esta haciendo bien su trabajo. Esto es lo que eval-agent consume.

Los dos KPIs core

KPI 1: Cobertura
¿Cuantos proyectos estan cubiertos?
cobertura = validated / total_projects
validated: En Qdrant + NotebookLM confirmado
synced: En Qdrant pero sin validar por NLM
stale: Tiene commits sin procesar
pending: Registrado pero no indexado
Ejemplo: 8 proyectos, 5 validated, 2 synced, 1 stale
Cobertura = 5/8 = 62.5%
Cobertura parcial (synced+validated) = 7/8 = 87.5%
KPI 2: Coherencia
¿Erudito responde igual que NotebookLM?
coherencia = pass / total_probes
1. Tomar preguntas del ultimo rondin (de nlm_notes)
2. Hacerle las mismas preguntas a Erudito (solo Qdrant)
3. Comparar respuestas via LLM judge
4. Si la respuesta de Erudito es coherente → pass
5. Si diverge significativamente → fail
Ejemplo: 10 preguntas, 8 coherentes, 2 divergen
Coherencia = 8/10 = 80%
Umbral aceptable: >= 70%

KPIs secundarios

Freshness
Tiempo promedio entre commit y sync. Ideal: < 30 min (2 ciclos de 15 min).
Metadata
% de archivos con frontmatter completo (no auto-enriched). Mide compliance de los agentes.
NLM Health
% de llamadas exitosas a NotebookLM en las ultimas 24h. Si baja del 50% → auth probablemente caduco.
Query Hit
% de queries respondidas con confianza alta (score >= 0.75). Mide calidad del conocimiento indexado.

Endpoint /metrics (lo que Erudito expone)

{ "coverage": { "total_projects": 8, "validated": 5, "synced": 2, "stale": 1, "pending": 0, "coverage_pct": 62.5, "coverage_partial_pct": 87.5 }, "freshness_avg_minutes": 22, "metadata_compliance_pct": 78.0, "nlm_health_24h_pct": 95.0, "query_hit_rate_pct": 82.0, "last_scan": "2026-03-18T02:15:00Z" }

Decisiones de diseno

  • Cobertura dual: Reportamos coverage (solo validated) y coverage_partial (synced+validated). Asi sabes cuanto funciona vs cuanto esta totalmente validado.
  • Coherencia la ejecuta eval-agent, no Erudito: Erudito expone los datos (nlm_notes + search). Eval-agent hace la comparacion y el LLM judge. Separacion de responsabilidades.
  • NLM Health como early warning: Si baja del 50% es casi seguro que la auth caduco. No emite alerta al mesh (por ahora) pero lo loggea para que tu lo veas en /metrics.
  • Probes rotativos: Las preguntas que eval-agent usa para medir coherencia se rotan automaticamente con cada rondin. No son estaticas — si el proyecto cambia, las preguntas cambian.
